1과목. 빅데이터 분석 기획

특강 — 전략 과목

타깃 13~14 / 20. 깊이는 얕다. 정의만 알아도 11~12. 저장 3분법·ODS/DW/Lake·비식별 세분·품질 5에서 +1~2를 만든다. ADSP/ADP 데이터 처리 기술과 문항이 겹친다. 1과목 + 4과목을 한 과목처럼.

이 과목의 고정 축 (특강: 3·4·7번은 항상 출제 구조)
1. 데이터 구조 → 정형 / 반정형 / 비정형
2. 저장 방식 → RDB / NoSQL / HDFS
3. 저장소 흐름 → ETL · ODS · DW · DM · Data Lake

시험은 정의 40% + 옳지 않은 것 20~30%. 정의만 외우면 40%에서 멈춘다. 차이점 한 줄을 같이 외워라.

1장. 빅데이터의 이해

1-1. 데이터 vs 정보, DIKW ★

단계 정의 예
Data 가공 전 사실 A대리점 100만, B 200만
Information 패턴 인식 A가 더 싸다
Knowledge 예측·활용 A에서 사면 이득
Wisdom 창의적 판단 A의 다른 제품도 쌀 것이다
  • 데이터 = 객관적 사실 / 정보 = 의미 부여
  • 3V(가트너): Volume, Variety, Velocity → 5V: + Value, Veracity
  • 활용 3요소: 인력·자원(데이터)·기술 ☞ 인자기
  • 출현 배경 ★: 스마트폰, 저장비용↓, 클라우드, 하둡, IoT
  • 함정: “직관적 의사결정의 중요성 증가”는 배경 아님 (데이터 기반이 핵심)
  • 단위: PB < EB < ZB < YB ☞ 패엑제요
  • SECI ☞ 공표연내: 공통화(암→암) · 표출화(암→형) · 연결화(형→형) · 내면화(형→암)
  • 가치 산정이 어려운 이유: 누가 언제 쓸지 모름 + 새 기법으로 무가치 데이터가 가치화
  • 변화 ☞ 전후양상: 전수조사, 사후처리, 양, 상관관계

1-2. 정형 · 반정형 · 비정형 특강 100%

특강 키워드

정형 = 스키마 / 반정형 = 메타데이터·태그 / 비정형 = 구조 없음 반정형 종류를 묻는 문항이 대부분을 차지한다.

유형 키워드 예 함정
정형 고정 스키마, 행·열, SQL RDB, CSV, ERP/CRM/SCM
반정형 스키마 없이 태그·메타데이터 JSON, XML, HTML, 웹로그, RFID, 센서 “구조 변경 불가”(X)
비정형 구조 없음 이미지·영상·음성·SNS·자유텍스트 전처리하면 정형화 가능(O)
  • JSON ★: 자바스크립트 기반 키-값 쌍 텍스트
  • 정량(수치) vs 정성(언어·인터뷰 텍스트)
  • 내부 vs 외부, 가역 vs 불가역도 가끔

1-3. 저장 방식 3분법 특강 변별력

특강

RDB / NoSQL / Hadoop HDFS 차이점이 1과목에서 13~14를 가르는 문항. 디테일만 외우고 근본 차이를 놓치면 문항을 읽어도 이해가 안 된다.

RDB NoSQL HDFS (하둡)
스키마 선정의, 엄격 (Schema-on-Write) 유연·스키마리스 파일 단위, 스키마 약함
일관성 ACID, 정규화 BASE, eventual 복제 3벌, 내결함
확장 수직 확장 중심 수평 확장 노드 추가 수평 확장
처리 트랜잭션·조인 단순 조회·대규모 배치, 높은 처리율
실시간 좋음 (OLTP) 유형에 따라 부적합 (파일 기반)
데이터 정형 반정형·비정형 강점 모든 원본 파일

함정 세트
- HDFS를 “낮은 응답 지연(실시간)”이라고 하면 오답. 설계 목적은 높은 처리율(throughput), 배치.
- NoSQL = “SQL을 안 쓴다”가 아니라 Not Only SQL (비관계형 + 수평확장).
- RDB만의 특징: 조인·정규화·강결합 스키마·트랜잭션.

1-4. ETL · ODS · DW · DM · Data Lake 특강 100%

OLTP(현업 운영) → ODS(운영 임시 통합) → ETL → DW(전사) → DM(부서) → OLAP/BI
                              ↘ Data Lake(원본 그대로, 하둡/S3)
용어 한 줄 특강 포인트
ETL Extract → Transform → Load 운영DB → DW. 추출·변환·적재 기능 정의
ODS Operational Data Store. 현업 운영 저장소의 통합 중간층 ADP와 동일 문항. 이번 회 예상
DW 전사 분석용. Inmon 4특징: 주제지향·통합·시계열·비휘발성 함정: ‘확장성’은 4특징 아님
DM 부서·주제별 소규모 DW DW의 부분집합
Data Lake 정형~비정형 원본 포맷 그대로 Schema-on-Read
DW 구조를 먼저 만들고 저장 Schema-on-Write
특강 강력 예상

Lake = 포맷을 정하지 않고 가져온다 (스키마 온 리드). DW = 포맷을 만들어 놓고 저장 (스키마 온 라이트).

OLTP vs OLAP
- OLTP = 거래 실시간 입력수정삭제 / OLAP = 다차원 대화식 분석
- OLAP 5연산: Roll-up, Drill-down, Slice, Dice, Pivot
- BI = 무슨 일이 있었나 / BA = 왜, 앞으로 어떻게
- 내부 DB 활용 예: ERP·CRM·SCM. 외부 SNS 분석은 내부 활용 아님 ★

1-5. SQL 분류 ⚠

명령 역할

DML SELECT INSERT UPDATE DELETE 내용물
DCL GRANT, REVOKE 권한

1-6. 분석 가치 4유형 특강

1·2·3·4번(쉬운 정의)은 누구나 맞춘다. 5번이 나만의 변별.

유형 질문 예
묘사적 Descriptive 무슨 일이 일어났나 대시보드, 리포트
진단적 Diagnostic 왜 일어났나 드릴다운, 원인 분석
예측적 Predictive 무슨 일이 일어날까 회귀, 분류, 시계열
처방적 Prescriptive 무엇을 해야 하나 최적화, 추천 액션

(특강 구어: “예방적”으로 들리기도 함 → 표준 용어는 예측적·처방적로 정리)

1-7. 마이데이터 · 산업 흐름

처리(프로그래밍) → 통합(DBMS) → 분석(빅데이터) → 연결(API·오픈데이터) → 권리(마이데이터)
- 마이데이터: 정보주체가 본인 정보를 제3자에게 제공하게 하여 서비스를 받음
- 특강: 정의 문제 가중치는 떨어짐. 다만 프로세스 순서는 시험을 좋아한다.

2장. 빅데이터 기술 및 제도

2-1. 플랫폼 3계층 특강 (최근 가중치 최고)

수집 → 저장 → 처리분석 → 서비스시각화 를 한 환경에서.

계층 역할 예 빨간 키워드
소프트웨어 수집·정제, 처리·분석, 사용자 서비스 Kafka, Spark, Hive, BI, 알고리즘 시각화·분석 알고리즘은 여기
플랫폼 데이터·자원 관리, 스케줄링, 프로파일링 Hadoop, YARN 작업 스케줄
인프라 서버·스토리지·네트워크, 자원 배치 서버, 디스크, 망 물리 자원

특강: 소프트 다음엔 플랫폼이 나올 타이밍. 특징 문장으로 계층을 고르는 문항.

2-2. 하둡 코어 + 에코시스템 특강

코어: HDFS(저장) + MapReduce(처리) + YARN(자원) + Common

HDFS 특강 100%

  • 구글 GFS를 모사한 클론. NameNode(마스터, 메타데이터) + DataNode(슬레이브, 블록 저장, 복제 기본 3)
  • 블록 크기 변경 가능. 대용량 특화 (소규모 파일에 부적합)
  • 낮은 지연 시간보다 높은 처리율. 실시간 X, 배치 O
  • 내결함성 = 일부 노드 죽어도 복제본으로 계속 동작

NameNode vs DataNode 역할을 섞어 놓고 틀린 설명 찾기 = 출제 포인트.

MapReduce 특강

  • Map(키값 변환) → Shuffle&Sort(같은 키) → Reduce(집계)
  • 무공유(Shared Nothing): CPU·메모리·디스크가 노드마다 독립
  • “공유 아키텍처”라고 쓰면 오답
  • 디스크 기반 배치. 실시간·반복연산은 Spark(인메모리)

에코시스템 — 정의만 짧게 특강

도구 한 줄
Sqoop RDBMS ↔ Hadoop 정형 대량 전송
Flume 로그 수집·전송
Kafka 실시간 스트림 Pub/Sub
Spark 인메모리 고속 (배치+스트림+ML)
Hive HiveQL, 하둡 위 DW
HBase HDFS 위 컬럼 NoSQL, 랜덤 읽기쓰기
Zookeeper 분산 서버 조정(코디네이터)
YARN 클러스터 자원·스케줄
Pig 스크립트 ETL

흐름: Kafka/Flume 수집 → HDFS/HBase 저장 → YARN 자원 → Spark/Hive/MR 처리
함정: HBase는 파일시스템이 아님. JDBC는 분석 도구 아님. Zookeeper ≠ 로그수집.

특강: 사례를 주고 학습 유형 고르기. 4과목에도 스침.

전이학습: 사전학습 모델 재사용 / Fine-tuning / 지식증류
XAI, AutoML, MLOps, 생성형 AI 용어도 한 줄.

2-5. 개인정보 특강

개인정보 = 가명정보까지. 익명정보는 개인정보가 아니다. 익명 공개는 처벌 대상 아님.
다른 데이터와 결합해 식별 가능하면 법이 정하는 개인정보.
활용은 가급적 익명 원칙.

식별 복원 법 활용
개인정보 가능 — 적용 동의
가명정보 추가정보 없으면 불가 추가정보로 복원 가능 적용 통계·연구·공익은 동의 없이
익명정보 불가 복원 불가 미적용 자유

데이터 3법 ☞ 개정신: 개인정보보호법, 정보통신망법, 신용정보법 (위치정보법 X)
처리 원칙: 목적제한, 최소수집, 목적외 제한, 정확성, 안전성, 목적달성 시 파기
함정: “최대한 오래 보관”(X)

프라이버시 모델: k-익명성=연결공격 / l-다양성=동질성·배경지식 / t-근접성=쏠림·유사성
차등정보보호: 통계 결과에 확률적 노이즈

2-6. 비식별화 5기법 — 세분화 특강 강력예상

ADP보다 기사답게 세부 기술 정의가 나온다.

기법 한 줄 예 세부 (암기)

3장. 데이터 분석 계획

3-1. 분석 기획 4유형 ★

방법 앎 방법 모름
대상 앎 최적화 솔루션
대상 모름 통찰 발견

3-2. 마스터플랜 우선순위 · ROI · 4V 특강

시급성(비즈니스 효과, Value) vs 난이도(투자비용, 3V: Volume Variety Velocity)
- 시급성 기준 순서: 3 → 4 → 2
- 난이도 기준 순서: 3 → 1 → 2
- ROI 관점: Volume·Variety·Velocity = 투자비용 / Value = 비즈니스 효과

분석 과제 위험 (4): 데이터 확보, 분석 기술, 분석 인력·조직, 범위·일정 등 — 정의 문항

의사결정 저해: 고정관념, 편향, 프레이밍

3-3. 하향식 vs 상향식 특강 가중치 높음

하향식 Top-down 상향식 Bottom-up
언제 문제가 명확 문제가 불명확, 데이터에서 문제 정의
출발 비즈니스 문제 데이터
절차 문제탐색 → 정의 → 해결방안 → 타당성 What 관점 인식, 비지도와 친함
특강 프로세스 순서 출제 프로세스 순서 출제

혼합: 발산(상향)+수렴(하향) / 디자인싱킹: 공감→정의→아이디어→프로토타입→테스트
문제탐색: 비즈니스모델캔버스 5 (업무·제품·고객·규제감사·지원인프라, 재무 없음)
거시: STEEP / 타당성: 경제·데이터·기술

3-4. 분석 방법론 3 + 빅데이터 방법론 특강 핵심 축

방법론 순서 키
KDD 선택 → 전처리 → 변환 → 마이닝 → 평가 DB 지식발견
CRISP-DM 업무이해 → 데이터이해 → 데이터준비 → 모델링 → 평가 → 전개 업데데모평전. 산업표준, 피드백
SEMMA Sample Explore Modify Model Assess SAS, 모델링 중심

빅데이터 방법론 5 ☞ PPADD
기획 Planning → 준비 Preparing → 분석 Analyzing → 시스템구현 Developing → 평가전개 Deploying

단계 넣을 것 / 넣지 말 것
기획 SOW, 위험관리(회피·전이·완화·수용=회전완수), WBS는 계획 수립
준비 수집·정제, 스토어 설계
분석 EDA, 모델, 검증·튜닝
시스템구현 운영 설계·구현·테스트
평가전개 모델 운영 주기·재학습 (분석 단계 아님 ★)

계층: Phase(단계) → Task(태스크) → Step
함정: KDD 전처리↔변환 뒤집기, CRISP 평가↔전개 뒤집기

개발모델: 폭포수 / 프로토타입 / 나선형(위험제거) / 애자일

3-5. 모형화 ≠ 모델링 특강

의미
모형화 변수 간 관계를 파악
모델링 수학적 함수식을 만듦

출제: 순서 + 모형화 정의.

데이터 확보 프로세스 가중치↓ / 데이터 분석 프로세스 가중치↑

4장. 수집 · 저장 · 품질

4-1. 수집 기술 — Sqoop vs Open API vs FTP 특강 이번회 예상

기술 대상 특강 한 줄
Sqoop 정형, RDBMS ↔ Hadoop 정형 수집 소프트웨어로 기억
Open API 정형·반정형·비정형 모두, 실시간 수집도 가능 “API는 정형만”이면 오답
FTP 파일 전송 (CSV, 로그파일) 파일 프로토콜. 실시간 로그 스트림 아님
ETL 추출변환적재 저장소 적재 과정
크롤링 웹 공개 페이지 화면 데이터
Flume/Kafka 로그·스트림 FTP와 혼동 금지
FGI 소수 전문가 토의 정성 ★

4-2. 변환 = 전처리 + 포맷통일 + 후처리 특강

여러 출처(API, JSON, RDB) → 전처리로 일관 포맷 → 저장 → 후처리

예
전처리 정제, 결측·이상 처리, 형변환, 필터, 포맷 통일 이전·직전 작업
후처리 저장 이후 집계, 인덱싱, 압축, 파티션, 요약마트

출제: 전처리에 해당하는 것 / 후처리에 해당하는 것.

4-3. 데이터 품질 특강 100% (빅분기 고유)

정형 품질 기준 5 (특강: 거의 100% 정의 문제)
완전성, 유일성, 유효성, 일관성, 정확성

기준 한 줄
완전성 필수값 누락 없이
유일성 동일 개체 중복 없이
유효성 정의된 규칙·허용범위 (형식, 코드) ★
일관성 시스템·항목 간 모순 없이
정확성 실제 세계와 일치

(교재 확장 7에 최신성·접근성·보안성이 더해지기도 함. 5가 특강 버전. 희소성은 품질 차원 아님)

진단 3단계: 대상 정의 → 진단 실시 → 결과 분석
개선 3단계: 계획 → 수행 → 통제

4-4. 분산 파일 시스템 vs DB 클러스터 특강 변별력

분산 파일 시스템 DB 클러스터
단위 파일·블록 레코드·테이블
예 GFS, HDFS Oracle RAC, 병렬 DBMS
강점 초대규모, 처리율, 저비용 질의·트랜잭션·일관성
약점 실시간·랜덤 I/O, 작은 파일 비정형 초대용량에 비쌈
처리 배치 (MapReduce) SQL OLTP/OLAP

대표 DFS: 구글 GFS, 하둡 HDFS

4-5. NoSQL 4유형 특강 마지막 변별력

특징: 스키마 유연, 수평확장, BASE, 비조인 중심. 종류별 도구 매칭.

유형 특징 도구
Key-Value 가장 단순, 캐시·세션 Redis, Memcached
Column 열 단위, 압축·확장 HBase, Cassandra, BigTable
Document JSON 문서 MongoDB, CouchDB
Graph 노드-관계 Neo4j

척도 4종 (2과목과 공유, 1에서도 수집계획에 출제)

명목(구분) · 서열(순위) · 등간(절대0 없음, 온도℃) · 비율(절대0, 무게)

시험 직전 체크리스트 (1과목)

  1. 정형=스키마, 반정형=JSON/XML/메타데이터, 비정형=영상·SNS
  2. RDB vs NoSQL vs HDFS — 실시간은 RDB, 배치는 HDFS, 유연확장은 NoSQL
  3. Lake = Schema-on-Read / DW = Schema-on-Write / ODS = 운영 임시통합 / DW 4특징에 확장성 X
  4. ETL 기능, MapReduce = 배치 + 무공유. “공유 아키텍처”면 오답
  5. NameNode=메타, DataNode=블록. HDFS는 높은 처리율, 낮은 지연 아님
  6. 계층: 알고리즘·시각화=소프트웨어 / YARN·스케줄=플랫폼 / 서버=인프라
  7. Spark=인메모리, Hive=SQL DW, Kafka=스트림, Sqoop=RDB↔하둡, Zookeeper=조정
  8. 가명=복원가능·법적용 / 익명=복원불가·법미적용 / 데이터3법=개정신
  9. 비식별 5 + 세부기술 (교환, 부분총계, 범위화, 잡음)
  10. 품질 5: 완전·유일·유효·일관·정확 / 진단3 · 개선3
  11. Sqoop=정형, API=전유형+실시간가능, FTP=파일
  12. 전처리 vs 후처리
  13. 하향식=문제명확, 상향식=문제불명확+데이터출발, 순서
  14. CRISP: 업데데모평전 / 빅데이터: 기획-준비-분석-구현-전개 / 운영주기=전개
  15. 모형화 ≠ 모델링
  16. 집중/기능/분산, 소프트스킬, 준비도·성숙도 → 도입형·확산형
  17. 거버넌스: 원칙·조직·프로세스 / 위기 통제 바꿔치기
  18. 분석 4유형 묘사·진단·예측·처방 / ROI: 3V=비용, Value=효과
  19. 학습유형 사례 + 준지도
  20. NoSQL 4종 도구 / DAS·NAS·SAN / GRANT=DCL

OX · 응용 훈련 (가리고 답하기)

1. 가명정보는 추가 정보와 결합해도 절대 복원할 수 없다.

정답X — 복원 가능. 복원 불가 = 익명정보.

2. Data Lake는 Schema-on-Write, DW는 Schema-on-Read이다.

정답X — 반대. Lake=Read(일단 넣고 나중에 스키마), DW=Write.

3. HDFS는 낮은 응답 지연의 실시간 처리에 최적화되어 있다.

정답X — 높은 처리율·배치. 실시간은 Spark/Kafka 쪽.

4. MapReduce는 노드가 CPU·메모리·디스크를 공유하는 공유 아키텍처이다.

정답X — 무공유 Shared Nothing.

5. Open API는 정형 데이터만 수집한다.

정답X — 정형·반정형·비정형, 실시간 수집도 가능.

6. JSON은 반정형이고, 키-값 쌍 텍스트이다.

정답O

7. 분석 대상을 알고 방법을 모르면 ‘통찰’이다.

정답X — 그건 솔루션. 통찰 = 대상 모름 + 방법 앎.

8. CRISP-DM의 첫 단계는 데이터 이해이다.

정답X — 업무(비즈니스) 이해.

9. 모델 운영 주기·재학습 전략은 데이터 분석 단계에서 정한다.

정답X — 평가 및 전개 단계.

10. 집중형 조직은 현업 요구에 즉각 대응하기 쉽다.

정답X — 분산형의 장점. 집중형은 병목.

11. DW Inmon 4특징: 주제지향, 통합, 시계열, 확장성.

정답X — 네 번째는 비휘발성. 확장성 아님.

12. 알고리즈미스트는 책임 원칙 훼손의 통제 방안이다.

정답X — 데이터 오용의 통제. 책임원칙은 ‘실제 결과만 책임’.

13. Redis=키값, MongoDB=문서, HBase=컬럼, Neo4j=그래프.

정답O

14. 모형화는 수학적 함수식을 만드는 것이고, 모델링은 변수 관계 파악이다.

정답X — 반대.

15. 정형 품질 5: 완전성·유일성·유효성·일관성·정확성.

정답O (특강 버전)

16. 하향식은 문제가 불명확할 때, 데이터에서 출발한다.

정답X — 그건 상향식. 하향식 = 문제 명확, 비즈니스 출발.

17. 시각화 알고리즘은 인프라스트럭처 계층이다.

정답X — 소프트웨어 계층.

18. GRANT/REVOKE는 DML이다.

정답X — DCL.

19. k-익명성은 연결 공격을 방어한다.

정답O. l=동질성·배경지식, t=쏠림·유사성.

20. 연봉 4500만을 4000~5000만으로 바꾼 것은 마스킹이다.

정답X — 범주화(범위화).
